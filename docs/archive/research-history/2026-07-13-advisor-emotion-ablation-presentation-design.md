# 情绪识别消融实验导师汇报 PPT 设计说明

## 1. 汇报目标

用约 15 分钟向导师说明：本次 Codex CLI 情绪识别消融实验获得了初步结果，但更重要的是识别出两个无效消融处理；因此当前证据适合用于形成下一轮实验设计，不适合直接下组件级因果结论。

汇报结束时，导师应当清楚：

1. 系统比较了哪些组件与配置；
2. 哪些对比真正改变了模型输入，哪些只是重复运行；
3. 当前结果能支持什么结论、不能支持什么结论；
4. 下一轮如何改造数据集和评测流程，才能得到可信的组件贡献证据。

## 2. 受众与语气

- 受众：熟悉机器学习研究方法、关心实验有效性和后续研究价值的导师。
- 语气：学术、诚实、结论先行；主动说明实验缺陷，但将其转化为可执行的研究改进。
- 深度：突出实验设计、证据边界和研究判断，弱化代码实现细节。
- 时间分配：11 页，主体约 13 分钟，预留约 2 分钟提问。

## 3. 核心叙事

叙事采用“研究问题 → 消融设计 → 实验结果 → 有效性诊断 → 下一轮研究计划”的结构。

主线结论：

> Seed-64 上，静态示例配置优于动态检索，完全移除示例与情绪历史后性能下降；但情绪历史与上下文长度两项消融因输入未发生变化而无效，组件级贡献仍需重新设计实验验证。

证据边界：

- `no_dynamic_examples` 与 `zero_shot` 的 Prompt 确实发生变化，可以进行探索性比较。
- `no_emotion_history` 与 `short_context` 的 64/64 条 Prompt 均与 `full` 相同，只能视为随机性重复对照。
- `zero_shot` 同时移除了 few-shot 示例与情绪历史，是组合消融，不能单独归因。
- 基准为 64 条合成样本，高上下文样本为 0；结论不能外推为正式模型能力排名。

## 4. 幻灯片结构

### 第 1 页：封面

- 标题：面向对话情绪识别的 Prompt 组件消融实验
- 副标题：Codex CLI Agent · Seed-64 合成基准 · 导师汇报
- 页脚：日期 2026-07-13
- 口头目标：一句话交代本次汇报既讲结果，也讲实验有效性诊断。

### 第 2 页：研究问题——哪些 Prompt 组件真正有用？

- 展示系统可能依赖的三个信息源：示例选择、情绪历史、上下文长度。
- 提出三个问题：动态示例是否优于静态示例；历史先验是否有效；更长上下文是否必要。
- 页面结论：消融实验必须同时验证“指标变化”和“处理确实生效”。

### 第 3 页：实验对象——从对话到 32 类情绪标签

- 用流程图展示：对话输入 → 上下文/历史组织 → few-shot 示例 → Codex CLI Agent → 情绪标签。
- 标注本实验评估的是 Agent 执行链路，不是裸模型 API。
- 页面结论：Prompt 构造是本实验的主要干预对象。

### 第 4 页：五组配置——原计划如何拆解组件贡献

- `full`：完整配置，作为基线。
- `no_dynamic_examples`：关闭动态示例检索，保留静态示例。
- `no_emotion_history`：计划移除情绪历史。
- `short_context`：计划缩短上下文。
- `zero_shot`：同时移除示例和情绪历史。
- 使用“保留/移除”矩阵，明确 `zero_shot` 是组合消融。

### 第 5 页：数据与评测——小规模、双语、可复现

- 64 条合成 seed 样本：中文 32、英文 32，共 32 个标签。
- 上下文依赖：none 14、low 22、medium 28、high 0。
- 5 组 × 64 = 320 次调用，全部成功。
- 指标：Accuracy、Macro F1；逐 case_id 比较 Prompt 是否改变。
- 环境：Codex CLI 0.142.4，模型 gpt-5.5；执行中断后断点续跑。
- 页面结论：这是探索性基准，重点是比较趋势与验证实验处理。

### 第 6 页：主结果——静态示例配置在 Seed-64 上最好

- 使用并列条形图展示 Accuracy 与 Macro F1。
- 重点标出：
  - `full`：71.88% / 65.76%
  - `no_dynamic_examples`：79.69% / 74.60%，较 full +7.81 / +8.83 个百分点
  - `zero_shot`：67.19% / 60.83%，较 full -4.69 / -4.93 个百分点
- `no_emotion_history` 和 `short_context` 使用淡色或警告纹理，提示不能作组件归因。
- 页面结论：当前基准中，动态检索没有超过静态示例；完全去除示例/历史的组合配置最弱。

### 第 7 页：关键发现——两个“消融组”其实没有发生消融

- 用 64/64 Prompt 相同的证据展示：
  - `no_emotion_history`：数据没有可移除的情绪历史字段。
  - `short_context`：样本历史最多一轮，截短后输入未改变。
- 对比 `no_dynamic_examples` 和 `zero_shot` 的 0/64 Prompt 相同。
- 将两个 no-op 组重新定义为“随机性重复对照”。
- 页面结论：指标不同不等于组件有效；必须先通过 treatment validation。

### 第 8 页：语言切片——中英文趋势基本一致

- 展示 full、no_dynamic_examples、zero_shot 的中英文 Accuracy/Macro F1。
- 重点：静态示例配置在中文和英文上都提高；zero-shot 在两种语言上都下降。
- 不放大 32 条/语言的小样本差异。
- 页面结论：主要趋势跨语言一致，但切片规模不足以讨论语言优劣。

### 第 9 页：错误模式——模型混淆的是相邻情绪边界

- 以“相邻概念对”呈现典型混淆：
  - sad → lonely
  - afraid → anxious
  - terrified → afraid
  - ashamed → embarrassed
  - confident → prepared
  - anticipating/apprehensive → anxious
  - sentimental → nostalgic
- 配一条中英平行错误样例，说明语义合理但标签边界细。
- 页面结论：后续提升重点可能是标签定义、边界示例与判别依据，而非单纯增加上下文。

### 第 10 页：可以下什么结论，不能下什么结论

- 左侧“当前证据支持”：
  - Seed-64 上静态示例优于当前动态检索策略。
  - 示例/历史组合整体比 zero-shot 更有效。
  - 主要错误集中于相邻情绪类别。
- 右侧“当前证据不支持”：
  - 情绪历史的独立贡献。
  - 长上下文的独立贡献。
  - few-shot 与历史先验谁贡献更大。
  - 对真实数据或裸模型 API 的泛化结论。
- 页面结论：本轮价值是形成可信的研究假设，而不是给出最终性能结论。

### 第 11 页：下一步——先修复实验可辨识性，再扩大规模

- 四步研究计划：
  1. 构造多轮长上下文样本，并补充 high-context 切片；
  2. 加入不会泄漏目标标签的历史情绪先验字段；
  3. 将 zero-shot 拆成独立的 no-examples 与 no-history；
  4. 多随机种子重复、显著性/置信区间，并考虑裸 API 评测。
- 收束句：下一轮目标不是“跑更多”，而是让每个消融都真正改变唯一变量。
- 留出导师讨论点：是否优先扩充真实对话数据，或先完成可控合成基准。

## 5. 视觉与版式

- 比例：16:9。
- 风格：简洁学术型；深海军蓝为主色，青色表示有效证据，暖琥珀表示警告/局限，灰色表示无效处理。
- 标题：使用结论式标题，不使用中性章节名。
- 字号：封面标题不低于 50 pt；页标题不低于 35 pt；正文不低于 16 pt。
- 图形：优先使用原生 PowerPoint 形状、条形图、矩阵与流程图；不使用装饰性图库图片。
- 信息密度：每页一个核心结论，正文控制在 3–5 个要点；详细数字只保留能够支撑结论的部分。
- 图表一致性：`full` 固定为深蓝，`no_dynamic_examples` 固定为青色，`zero_shot` 固定为暖橙；两个 no-op 组固定为浅灰并附警告标记。
