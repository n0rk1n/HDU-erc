## 1. 比较内容

| 组别 | 方案 | 固定部分 | 要回答的问题 |
|---|---|---|---|
| A | 专用情绪分类器 | 现成 GoEmotions 分类模型；冻结参数，28 维 sigmoid 分数与验证集选定阈值 | 不调用大模型时的质量与成本基线是什么？ |
| B | DeepSeek＋BGE 检索 | 固定 DeepSeek 版本、提示词、4 个训练集示例；BGE 普通相似度排序 | 通用语义检索的效果如何？ |
| C | DeepSeek＋情绪专用检索 | 与 B 相同，仅替换检索编码器及其必需的编码方式 | 情绪表示是否比通用语义表示更适合选例？ |
| D | 专用分类器＋DeepSeek 核验 | 复用 A 的原始预测与阈值；按固定规则送审 | 大模型核验能否改善专用分类器，代价是多少？ |

主要对比为 C−B（检索表示）；关键次要对比为 D−A（核验价值）。A 与 B/C 是整体系统对比，不能解释为单因素因果效应。多项显著性检验须预先指定校正方式。

B/C 第一轮都采用普通近邻选例，不同时引入对比标签对、重排或动态示例数。固定同一 train 示例库、相同输入文本、4 个示例、示例格式、顺序规则、去重规则和并列排序规则。每组保留检索索引与实际示例 ID。检索池不足或上下文超限的处理应在运行前统一。

D 默认采用困难样本送审，其余样本原样保留 A 输出。核验器接收文本、A 的候选标签与明确区分为模型分数的数值；可保留、删除、添加原生标签。首轮不引入检索示例，以免混入额外机制。新增标签不得被 A 的候选集合硬性截断。具体送审规则、阈值、核验提示词在校准数据上确定并冻结；报告送审比例、修正正确数和改错数。若后续改为全量核验，应单列协议版本。

## 2. 共同规则

- 数据：GoEmotions 官方英文单条评论，27 种情绪＋neutral，保留原生多标签及 neutral，不自行合并标签或删除困难样本。
- 模型：使用现成模型，不更新模型参数。A/D 共用一个专用分类器；C 优先复用该模型的编码器，但必须事先确定表示提取层、池化、归一化及距离。分类头输出与检索向量是不同产物。
- 训练暴露：专用模型可能接受过 GoEmotions 监督训练，须记录其训练数据与 dev/test 使用情况。不能将整体对比描述为相同监督资源预算。
- 划分：train 仅用作检索库及必要的训练内方法设计；dev 划分互不重叠的校准/开发与独立确认子集，排除已经反复分析的历史切片。确认集大小、ID、种子与哈希在运行前确定，样本不足时先调整设计，不伪称独立。官方 test 留到方法最终确定后。
- 校准：先统一阈值，再视支持数考虑逐类阈值；仅在校准集选择。预先定义空预测集合回退，不擅自规定 neutral 与所有情绪互斥。A/D 使用同一决策规则。
- 调用：B/C/D 使用相同 DeepSeek 模型版本、生成参数及可比的输出预算，固定重试/超时/解析规则；D 的输入形式不同，单独保存核验提示词。API 返回的实际模型标识和运行时间须留存。
- 评分：主指标 Micro-F1；辅以 Macro-F1、每类 P/R/F1/支持数、exact match、多标签与 neutral 子集表现、预测标签数。相同样本配对评估，保留失败，不因失败改变各组分母。
- 稳定性：正式含 LLM 的组至少独立重复 3 次，重复间固定示例与索引。A 在确定性设置下可缓存复用；D 复用 A 预测。分别报告样本配对区间与运行间波动，不以单次最高分代表方法。
- 成本：报告端到端延迟、检索/分类开销、LLM tokens、实际费用及 D 送审比例；同时说明模型加载与索引构建是否计入。

## 3. 正式冻结前必须补齐的运行清单

以下尚未确定，不将草案冒称已冻结协议：

1. 专用分类器、BGE、DeepSeek 的精确模型 ID/revision；专用模型训练暴露；C 的编码方式。
2. 数据版本、历史使用样本清单、校准/确认集 ID 与哈希、样本量和随机种子。
3. A 阈值选择目标与搜索范围、空集合处理；D 送审定义、阈值及核验提示词。
4. B/C 提示词与序列化、检索参数、截断策略；API 参数与失败计分方式。
5. 配对统计方法、多重比较规则、重复次数及费用上限。
6. 小规模接口/标签映射检查通过后，将以上配置和代码提交 SHA 写入不可变运行清单，再启动正式比较。

协议冻结意味着停止根据确认集结果修改这些规则，不意味着只能用一个模型。探索期可调整；正式确认后如需修改，建立新协议版本与新的独立评估安排。
