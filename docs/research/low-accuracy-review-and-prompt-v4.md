# 低分问题总复盘与 Prompt v4

本轮依据四组历史预测：v1/ranked、第一次 v2/contrastive、重复 v2、v3。历史 200 条样本的四组输出、缺失/多余标签、细类与大类命中、入选训练例子汇总在工件 `e3f95232-9642-4ac0-a0ec-a540f389046e`。统计与新增训练依据在 `a519b66c-e87e-4271-baa4-29cb06c8adea`。

## 已观察到的实际识别问题

| 问题 | 已有证据 | v4 对应调整 |
|---|---|---|
| 负面话题、否定、脏话被当成情绪 | v2 两轮 disapproval 误报 52/55 次；原生真值只 7 条包含该标签 | 根据实际表达的拒绝/批评态度判断，不将其用于所有负面反应 |
| neutral 经常被误判，同时又会误吞真实情绪 | v3 在 60 条仅 neutral 中仍漏掉 36 条；neutral 误报从同期 v2 的 18 增到 26 | 先扫描所有情绪信号，再决定 neutral；事实内容不自动排除情绪，情绪话题也不自动排除 neutral |
| 多种候选解释被一起输出 | 真值平均 1.16 标签，v2 平均 1.44；早期完全匹配低而部分命中较多 | 区分备选与共现，不凭情绪相关性附加标签 |
| v3 过度收紧，减少误报也损失召回 | TP 99→93，FP 189→148，FN 133→139；至少一个命中 47%→44% | 去掉训练频率和最小集合倾向，不要求第二个情绪必须有另一句或不重叠的证据 |
| 部分低频/隐含情绪几乎不输出 | v3 的 disappointment 为 0/9 命中，realization 为 0/5；approval、caring 召回也下降 | 明确“失落/事情不如意”“注意到/得出结论”“简短认可”“提供帮助的建议”等表达边界；无需情绪名或强烈程度词 |
| 同大类内部易混 | annoyance/disapproval、admiration/approval、sadness/disappointment 等替代错误持续出现 | 先比较含义，再检查是否真的同时表达；不强制同一家族互斥 |
| 话题相似不能保证示例有效 | 现有词面 Jaccard 不度量情绪含义；第一轮实际更换示例的 62 条 Micro-F1 从 39.51% 降到 34.73% | 提醒按表达及说话目的比较示例，标签不限于检索结果；本轮不改检索，不能据此证明检索本身已修复 |
| 通用定义与训练标注习惯有偏差 | 训练集中存在同情性 sorry→remorse、直接建议→caring、普通观察→realization；短文本标注有难解释的个案 | 保留数据支持的宽泛用法，不把标签定义写成必要关键词或过窄条件 |
| 讽刺、幽默、引用与说话对象容易误读 | 既有把普通陈述当玩笑的误报，也有把实际情绪仅当成事实的漏报 | 同时阅读否定、对象和整句用途；不补造上文或讽刺，不要求第一人称才能有情绪 |

不能把所有个案归因于同一个原因。四组都没有细类交集的样本为 77 条，说明存在持续困难；但不能仅凭模型与标注不一致，就断定公开标注错误。

## 会影响分数解释、但不能直接当成模型误判根因的因素

1. **精确集合匹配较严格。** 多一个或少一个标签都不完全匹配；Micro-F1 已经给部分命中计分，不能用“标准太严”解释所有低分。
2. **大类合并改变了任务难度。** families 得分反映较粗的方向；任一命中忽略多报。原生标签没有主副排序，不能把无序数组前两个当 Top-2。
3. **切片较小且类别不均衡。** dev200 中 172 条单标签，3 类没有真值支持，若干类只有 1–2 条。28 类 Macro-F1 的零分母按 0，因此少数类结果不稳。
4. **完全匹配率需要参照。** 对这批数据一律输出 neutral 的离线常量基线，exact match 为 30%，Micro-F1 为 28.24%。这不是模型调用结果，也不是推荐策略；它说明不能仅用 exact match 宣称方案有效。v3 的 exact match 为 27%，Micro-F1 为 39.32%。
5. **供应商重复调用有变化。** 两次 v2 的 200 个请求体哈希相同，77 条最终标签集合不同；Micro-F1 为 40.62% 与 38.08%。温度 0 不代表输出完全一致，供应商也未提供可核实权重修订号；不臆测变化的内部原因。
6. **初轮同时改了 prompt 和 example。** 所以整体或示例子集变化不能单独证明某一部件的作用。v3/v4 对照固定实际例子，隔离 prompt 改动。
7. **长提示不等于有效。** v3 相对同期 v2 输入 tokens 增加 21.33%，效果仍不稳定；长度是否导致误判尚无独立消融证据；固定的 low 推理预算也尚未单独消融，不能断言增加推理或更换模型就能改善。v4 改为先扫描、比较边界、双向复查，避免继续叠加单向限制。
8. **重复开发集会过拟合。** 本轮明确使用历史错误生成假设，属于开发迭代，不称为仅训练集调优或独立泛化评估。新 prompt 不包含 dev 原文/真值对；官方 test 保留。

## 已核实不应归咎的情况

- 正式两轮累计 800 条预测均最终成功；第一轮有 1 次带 JSON 围栏的响应，重试后有效。不能把这次格式重试解释为低准确率来源。
- 原始请求、响应、数据集真值、数据库预测和评分已成对核验，未发现把错标签存对、评分丢样本、超预算截断或最终接口失败导致本轮低分。
- 前轮训练审计脚本曾处理一条抽样文本的外层引号，已修正。全部统计、运行时训练原文、prompt 与模型输入不变；这不是模型低分原因。
- 旧 `emotion_examples.json` 是测试夹具，当前实验实际从完整 train 库检索。仅修改旧静态文件不能优化当前实验；本轮保持运行时入选例子不变。
- 当前 GoEmotions 查询与训练评论都是英文，不能将早期聊天项目可能存在的中英文检索问题直接套用到这次分数。

## 新增训练边界核验

按 Random(904)，从 train 中对 disappointment、realization、approval、caring、confusion、remorse 各抽 8 条，保留原文、完整标签和 source_id。采样代码为 `scripts/audit_prompt_history_v4.py`；旧 43,410 条统计及 280 个抽样记录沿用修正后的训练审计工件 `df0b445f-fe1b-4bea-bcb1-961f99778c41`。

例：`eeaeq6u` 求职受挫同时标注 disappointment/sadness；`eeu3t4i` 未兑现承诺标注 disappointment；`eevwyno` 普通“注意到”标注 realization；`edosowi` 强硬建议标注 annoyance/caring；`edwg2he` 标注 caring/neutral；`edj78oi` 标注 admiration/approval。它们支持放宽表达形式，而非要求所有标签都以显式情绪词或独立句子出现。

## 冻结对照

新增 `native-labels-v4`；v1/v2/v3 保持原文。使用重新运行的 v3 控制组与 v4 候选组，各 200 条，除 name/prompt_version 外配置相同，实际请求除 instruction 外相同。评分继续使用原生 28 类及同一解析器，保留全部失败/重试、用量及原始响应。

本轮只冻结一个 v4 候选；完成后报告 Micro/Macro-F1、precision/recall、exact match、命中率、每类变化、配对区间和 token 代价，无论结果改善或退步均保存。

## 本轮运行后的补充结论

结果见 [v4 对照报告](glm-dev200-prompt-v4-results-20260908.md)。v4 的 realization 命中从同期 v3 的 0/5 到 3/5，caring 从 2/7 到 5/7，disappointment 从 2/9 到 3/9；但总体 TP 只增加 3、FP 增加 50，neutral 命中从 30/61 降到 22/61，Micro-F1 从 42.55% 降到 39.39%。这说明本轮规则组合没有形成整体改进，不能仅凭局部类别回升采用新版，也不能分离每条规则的因果作用。v4 作为未获支持的候选保留，不提升为默认版本。
