## 3. 研究方向如何收敛

### 3.1 曾经讨论过的候选方向

| 方向 | 讨论时的依据 | 是否进入本轮实施 | 保留原因或暂缓原因 |
|---|---|---|---|
| 情绪转折感知与自适应识别门控 | 原聊天项目能决定识别还是复用旧情绪 | 未进入研究工程实验；旧门控已从研究分支移除 | 需要真实多轮、转折标签、漏检/延迟与成本评价 |
| 历史错误传播抑制 | 历史预测可能影响检索；助手措辞可能改变后续判断 | 未实施专项实验 | 需要保持语义与指代不变的扰动数据和人工核验 |
| 模糊/混合情绪与置信度校准 | 原项目有置信度与主次情绪输出 | 未做概率校准或拒答实验 | 现有数值置信度不等于经过校准的正确概率 |
| 易混情绪对比示例检索 | 词面/主题相似未必能区分相近情绪 | **主线，已实现初版并做实验** | 使用公开标注即可自动评价，符合现成模型路线 |
| 原文证据约束推理 | 希望减少照抄示例与补造上下文 | 有可选 evidence 输出能力，尚未做独立实验 | 正式四组 require_evidence=false；不能把接口能力当成效果验证 |
| 推理预算与检索证据自适应分配 | 历史代码存在不同 reasoning effort 配置的讨论 | 未实施 low/high 交叉或自适应策略实验 | 必须把初判、门控、复核等全部调用计入成本 |
| 点赞/点踩反馈用于优化 | 原聊天工程曾记录回复反馈 | 未转为情绪识别学习信号 | 回复满意度不是情绪标签真值；研究分支已移除该产品功能 |

早期代码检查发现过：英文种子示例与中文查询在词面检索上可能得到同一批零分回退例子。这是当时聊天工程的检索现象，不能证明最终分类必错，也不能直接解释后来英文 GoEmotions 实验的低分。

### 3.2 当前可以沿用的课题表达

工作题目可表述为：**面向易混情绪识别的检索增强提示构建方法研究**。

早期更宽的表述是“面向易混淆情绪的对比示例检索与证据约束推理方法研究”。目前证据约束尚无独立实验，因此不应将它写成已经验证的第二项贡献。

研究问题是：在分类模型和输入预算受控时，如何组合标签判定规则与有区分作用的训练示例，减少细粒度情绪的误报和漏报？

提示词与 few-shot 可以保持同一研究脉络：

```text
固定指令：定义任务、标签边界、如何使用示例
              ＋
动态示例：依据输入从 train 选择 4 条带标签评论
              ＋
待测原文：独立输入的一条评论
              ↓
同一现成模型 → 原生标签集合 → 固定评分
```

两部分可以分别消融，也可以测交互。当前实验已经完成这类分离，但没有证明两部分会自然叠加获益。

### 3.3 创新性边界

GoEmotions 数据集、使用大模型、接入 BGE、向量检索、few-shot、增加解释或 LangGraph/UI，单独都不足以作为方法创新。现有 contrastive-v1 是可复现实验起点，不能因为名称含“对比”就认定创新成立。

早期讨论已提及 InstructERC、EmoRationale、示例检索与改写等相邻研究；本次文档整理没有重新进行文献检索，也没有完成覆盖性综述。后续仍要核对：具体候选机制与既有方法的差异、控制条件下的收益、代价及适用边界。

### 6.2 ranked 与 contrastive-v1

普通 `ranked`：按既定相似度排序，在去重与输入预算允许的前提下取 4 条。词面方法使用 Jaccard，语义方法使用归一化向量点积即余弦相似度。

现有 `contrastive-v1`：

1. 使用与 ranked 相同的前 50 条候选。
2. 选择最高排名、非复制且预算允许的锚点。
3. 根据锚点的训练标签，在候选中找对应相邻标签的正相关例子；该例子含相邻标签、不含对应锚点标签。
4. 将合法对照提到第二位置，其余依照原相似度顺序补足。
5. 没有合适对照就回退；保存未入选原因、角色、标签对、原排名与最终顺序。

初版关系共 11 对：anger/annoyance、annoyance/disapproval、admiration/approval、joy/excitement、joy/relief、sadness/disappointment、sadness/grief、fear/nervousness、curiosity/confusion、realization/surprise、remorse/embarrassment。

这些关系是**语义先验**，不是已学习的混淆矩阵。对照标签不同不代表两条评论的其他标签完全互斥，也不保证主题以外存在足够判别信息。当前没有根据查询真值指定对照标签，也没有模型初判后再做第二次分类。

## 7. 评价口径与实验控制

### 7.1 “准确率”必须具体说明是哪种指标

| 指标 | 如何解释 | 用途与局限 |
|---|---|---|
| Micro-F1 | 所有样本的标签 TP/FP/FN 汇总后计算 2TP/(2TP+FP+FN) | 当前主比较；同时惩罚多报和漏报 |
| Macro-F1 | 分别算 28 类 F1 再平均，零分母按 0 | 观察长尾类别；200 条切片中稀有类很不稳定 |
| Exact match | 预测标签集合与真值集合完全相同 | 多一个或少一个都不算完全正确 |
| 任一细类命中 | 预测与真值至少有一个交集 | 不充分惩罚多报，必须配合 P/R/F1 和标签数 |
| Family F1/完全匹配 | 双方映射到 7 大类并去重后评分 | 衡量粗粒度方向，不能替代原生细类结论 |
| 任一大类命中 | 映射后的集合有交集 | 更宽松的补充诊断 |
| Micro-precision / recall | TP/(TP+FP)、TP/(TP+FN) | 判断提升来自减少误报还是找回漏报 |
| 最终失败/缺失率 | 全部计划样本为分母 | 失败按空集合计分，不丢掉难例 |

例如真值 sadness，预测 sadness＋joy：任一命中算命中，exact 不算完全正确，F1 会惩罚多出的 joy。当前原生标签为无序集合，没有经过置信度排序，因此“主副有一个命中”应命名为任一标签命中，不能直接叫 Top-2 准确率。

最早两组离线补充复算：细类任一命中 48%→50%，family exact 46%→47.5%，family 任一命中 61.5%→63%，family Micro-F1 55.28%→57.01%。新版仍有 100/200 条与真值完全无交集，不只是集合评分太严格。最早这次补充属于只读复算；后续各轮分析将相应诊断写入分析工件，结构化 metric_values 的具体字段以数据库为准。

旧 dev200 上常量 neutral 的离线参照：exact=30%，Micro-F1=28.24%。它没有调用模型，也不是推荐分类器；用来说明单看完全匹配率可能被类别比例误导。

### 11.2 P01：先区分方法效果与重复调用波动

目标不是把分数跑高，而是确认目前观察到的 +6.59 个百分点是否稳定。

建议保留 R5 的全部样本、实际请求、train 索引和 v1/v3；优先对 **A 与 B 成对做独立重复**，B 为重点候选。仅重复 B 可以看其绝对分数波动，但不足以估计 B−A 的稳定性，因此不应只复跑 B 后与旧 A 比较。

实施前需要写明：新增几次重复、组间顺序如何平衡或交错、总调用上限、是否沿用当前解析和重试策略、哪些统计作为主结论。每个独立重复产生新 run；不覆盖 R5，不通过 resume 跳过成功项冒充重复。

设新增重复数为 r，则 A/B 每次各 200 条：计划首轮调用为 `400 × r`，按现行每条最多两次尝试的最坏上限为 `800 × r`。这只是预算公式，r 尚未确定，也没有换算成未经核实的金额。

应输出：每次 A/B 的 Micro/Macro-F1、exact、B−A 差值；同请求标签集合一致率；FP/FN 波动；跨次均值/范围或标准差；实际调用和 tokens。统计方法应区分样本抽样与重复运行两层不确定性，不把所有重复输出当独立新样本堆起来。

验收：独立重复齐全、请求条件一致、旧记录不变；结论允许“稳定增益”“无法区分”“不稳定/退化”三种结果，不只接受正收益。

### 13.3 复算、重复与恢复分别是什么意思

| 操作 | 是否新调用模型 | 是否新增记录 | 适用场景 |
|---|---|---|---|
| SQLite 只读查询、读报告 | 否 | 否 | 核查进度和已有结果 |
| analyze/report 脚本 | 通常不调用模型 | 可能新增分析工件或报告 | 重算诊断，执行前读脚本，不笼统称作只读 |
| evaluate/compare/reparse | 不需要重新推理 | 会新增版本化结果 | 复算已有响应，旧评分不变 |
| resume 现有 run | 仅未完成/可重试部分可能调用 | 会追加尝试 | 故障恢复；不能作为独立重复 |
| 新建独立 run | 是 | 是 | 测量跨次模型波动或新方法 |
| storage backup | 否 | 活跃库可能登记清单 | 产生可迁移快照 |
