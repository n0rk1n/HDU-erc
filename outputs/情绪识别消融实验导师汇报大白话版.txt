情绪识别消融实验：给导师汇报的大白话版本

老师好，我这次想汇报的是情绪识别项目的一轮消融实验。先说结论：这轮实验更像一次“摸底”和“排雷”，不是要证明某个方案已经最终胜出，而是先确认哪些组件真的值得继续研究。

一、背景

我们现在做的不是简单的正负面情感分类，而是细粒度情绪识别：同样是负面情绪，难过、孤独、焦虑、害怕、羞愧之间要尽量分清；正面情绪里，自信、期待、怀旧等也不能混在一起。

原来的方案里，我放进了几类可能有帮助的信息：第一类是动态检索到的示例，相当于先给模型看几个相近的“参考题”；第二类是历史情绪信息，希望模型能结合前文判断；第三类是上下文长度，希望多给一些对话内容能提升判断。因为这些模块都加在一起时效果看起来还可以，所以这次要把它们分别拿掉，看看真正起作用的是谁。

二、目的

这轮实验主要回答三个问题：

1. 给模型示例，到底有没有帮助？动态找示例和固定示例，哪个更合适？
2. 去掉示例和历史情绪后，整体会退化多少？
3. 历史情绪和上下文长度，在当前实现里到底有没有真的进入模型输入？

换句话说，我这次不是只看“分数高不高”，还要检查实验设置是不是能支持我们下结论。

三、准备与做法

我准备了 64 条合成种子文本，其中中文和英文各 32 条，覆盖 32 种情绪标签。每一种实验设置都跑完这 64 条，所以一共是 5 组、320 次调用，最终全部成功返回。

基准组是完整方案，也就是保留动态示例、历史情绪和原来的上下文设置。对照组包括：把动态示例换成固定示例、完全零样本、去掉历史情绪、缩短上下文。

这里也要提前说明：这轮是通过 Codex CLI 的 Agent 调用链跑的，不是直接裸调模型 API。因此它反映的是“当前整套调用环境”的效果，后面还需要用更可控的裸 API 再复验一次。

四、结果怎么讲

完整方案的准确率是 71.88%，Macro F1 是 65.76%。

最显眼的结果是：把动态检索示例关掉、改成固定示例以后，准确率反而到了 79.69%，Macro F1 到了 74.60%。相对完整方案，准确率提高 7.81 个百分点，Macro F1 提高 8.83 个百分点。

这说明在这 64 条小基准上，动态检索没有体现出优势，甚至可能把不够贴切的示例带进来了；固定示例更稳定，模型反而更容易判断。但这个结论目前只能说是“值得继续验证”，还不能直接说动态检索一定不如静态示例，因为样本量还小，而且基准文本是合成的。

零样本组的准确率是 67.19%，Macro F1 是 60.83%，比完整方案低 4.69 和 4.93 个百分点。这至少说明：完全不给参考信息时，模型识别细粒度情绪会变弱，示例或者历史信息整体上是有价值的。

但这里有一个很重要的实验边界：zero-shot 同时拿掉了示例和历史情绪，只能说明“整体都拿掉”后变弱，不能说明到底是哪一项更重要。后续必须把“只去示例”和“只去历史”拆开做，才是干净的消融。

还有两组结果需要特别谨慎。no_emotion_history 和 short_context 的 64/64 条 Prompt 没有改变，因此不能从这两组指标解释组件贡献。也就是说，从日志看，这两个开关在当前这批数据和实现里没有真正改变送给模型的文本；它们和基准组之间出现的一点分数差，更像调用时的随机波动，不能解释成“历史信息有效”或者“长上下文有效”。

语言上看，完整方案的中英文准确率都正好是 71.88%，固定示例在两种语言上都有提升，零样本在两种语言上都有下降。这是一个方向一致的信号，但每种语言只有 32 条，也不适合做太强的语言结论。

从错误案例看，模型最容易在语义相近的标签之间混淆，比如把 sad 预测成 lonely，把 afraid、terrified 和 anxious 混在一起，把 ashamed 和 embarrassed 混淆，也会把 confident 预测成 prepared，把 sentimental 预测成 nostalgic。这说明后续更应该补“相邻情绪”的难例，而不是只增加容易判断的样本。

五、反思与边界

这轮实验最大的收获，不只是得到一个更高的分数，而是发现了实验设计里不能直接解释的地方。

第一，数据只有 64 条，还是合成文本，且高上下文样本数量是 0。既然没有真正的多轮、长上下文场景，就无法检验上下文截断到底有没有影响。

第二，历史情绪目前可能只是开关存在，但没有形成实际不同的 Prompt。要么修正注入逻辑，要么重新定义历史信息：不要直接泄漏标签，而是提供上文表达出来的情绪线索，再测它是否真有帮助。

第三，动态检索的失败也可能不是“检索不该做”，而是检索质量、示例筛选、示例格式或样本规模有问题。它目前告诉我们的是：固定示例是一个很强、很稳定的基线，动态检索必须先超过这个基线才值得保留。

六、下一步

下一步我准备做四件事：

1. 重做干净的单因素消融：只去示例、只去历史、只改上下文，确保每组 Prompt 确实不同。
2. 增加真实或半真实的多轮对话，特别是补足高上下文样本，验证上下文与历史信息的价值。
3. 扩大数据规模，并用不同随机种子重复跑，报告置信区间或显著性，避免被一次波动误导。
4. 用裸模型 API 复跑核心实验，把 Agent 环境因素和模型本身的能力区分开。

最后，如果用一句话总结这次工作：当前最可靠的发现是，示例对细粒度情绪识别有帮助，而固定示例在这轮小基准上比动态检索更稳定；至于历史情绪和上下文，目前还不能下结论，下一步要先把实验开关和数据场景补扎实。
